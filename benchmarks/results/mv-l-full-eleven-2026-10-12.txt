DEFECTS THIS RUN SHOWED
-----------------------
  1. `Error: index out of bounds` with a backtrace, 136 times on stderr (the "4 times during
     v4.34.1's cache fetch" of mv-l-full-2026-10-12.txt is the same thing). All 136 backtraces are
     one call site on a task thread; 136 = 34 calls x 4 workers. The parallel map's worker that
     finds the list exhausted cleared slot k = n of the pending array with `set!`, which panics out
     of range and returns the array unchanged — so no output was wrong, but every parallel map
     printed one panic per worker. Fixed in the commit that adds this log (`setIfInBounds`), and
     tools/lean-test-gate.sh now runs the test executable with LEAN_ABORT_ON_PANIC=1: with the
     old line put back it fails (the parallelMap invariant aborts, exit 134); with the fix,
     243 compile-time and 74 run-time hold and none panics (Apple M1, 2026-10-12).
  2. The memory sampler recorded no litedoc4 row in this run or in mv-l-full-2026-10-12.txt. The
     build was started as `$(time_cmd) litedoc4 ... &`; the command substitution runs inside the
     backgrounded process, so its subshell is the timer's first child, the sampler can take it for
     litedoc4, and once it exits the sampler never looks again (shown on an M1 with a slowed
     substitution: the first child seen is bash in 5 of 5). Fixed in the same commit (the time
     command is computed once, before anything is backgrounded); not yet seen on a runner.
