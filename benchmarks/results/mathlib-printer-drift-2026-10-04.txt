Mathlib printer drift: an old version's types printed by the newest Lean + Mathlib
=================================================================================
Date: 2026-10-04. Context: docs/multiversion/plan.md, D10 ("printing an old version with the
newest printer is an approximation, and it is accepted"). This run puts a number on that
approximation, isolated from real type changes: the SAME Expr (the old version's declaration
type) is printed by the old printer and by the new printer.

QUESTION
--------
For a Mathlib declaration of an old version, how often does the newest Lean + Mathlib print its
type (the old version's Expr, rebuilt verbatim) differently from how the old Lean + Mathlib
printed it? And, separately: how often does the declaration's own name exist in the newest
version with a different type (D10: "a declaration whose name exists in both versions with
different types can only be looked up as the newest one")?

CONDITIONS
----------
- Old: Lean 4.31.0 (commit 68218e876d2a), Mathlib v4.31.0 (fabf563a7c95a166b8d7b6efca11c8b4dc9d911f),
  built workspace <old-workspace> (the measurement target; read-only here).
- New: Lean 4.34.1 (commit 5045d0056413), Mathlib v4.34.1 (d13f23b723b8a846827a245b89c10fc7d3f11612),
  workspace <new-workspace> (Mathlib oleans from the cache).
- Hardware: Apple M1, 16 GB RAM (hw.memsize 17179869184), macOS 26.6.2. One process at a time;
  the two sides never ran concurrently.
- How Mathlib was loaded: the script's header is `import Lean` only and `main` calls
  `importModules #[{ module := `Mathlib }] ... (loadExts := true)` after
  `enableInitializersExecution` - the litedoc4 extractor's way. A header `import Mathlib` under
  `lean --run` would elaborate the file against Mathlib and then import Mathlib again inside
  `main` (two environments in one process; its memory cost was not measured). That Mathlib's
  delaborators were active on both sides was checked on the 20-record sample (ℝ, ‖x‖, ↑, ⇑, ⟶,
  Rˣ, set difference all printed by both).
- Printer: `Lean.Meta.ppExpr` of the full type, then `Format.pretty` at width 1,000,000; Core
  options = defaults plus `format.width` = 1,000,000; Core.Context.maxHeartbeats = 5,000,000
  (the extractor's value); a fresh MetaM state per record; exceptions caught per record with
  `tryCatchRuntimeEx`. No namespaces opened. Same code, same options on both sides (one script,
  compiled by each Lean).
- Comparison: whitespace runs collapsed to one space, then string equality.
- Runs (each side: a 20-record run first, then the 5,000-record run; the 20 records are the first
  20 of the 5,000; on each side the 20-record output equals the first 20 records of the
  5,000-record output, timing fields aside):
    old, 5,000: 81.10 s wall, 15.13 s user, 10.99 s sys, peak RSS 3.91 GB (3,910,975,488 B);
                of which importModules 50.2 s, enumeration 12.7 s, ppExpr total 5.5 s
    new, 5,000: 83.51 s wall, 20.12 s user, 10.74 s sys, peak RSS 4.13 GB (4,128,538,624 B);
                of which importModules 56.1 s, ppExpr total 5.1 s
  Wall >> user+sys on every run (also the 20-record runs: 69.6 s / 69.9 s wall), so by this
  repository's criterion none of them was warm; page faults ~550k-600k per run. The timings are
  context only - the subject of this measurement is printed text, which does not depend on warmth.

POPULATION AND SAMPLE
---------------------
- N = 311,415 documented declarations of Mathlib v4.31.0 (measured): every module whose name
  starts with `Mathlib.`, walked in `header.moduleNames` (import) order; a name listed by several
  modules belongs to the first (the extractor's main path, its `seen` set - not `const2ModIdx`);
  dropped: `recInfo`, and doc-gen4's `isBlackListed` as the extractor transcribes it (no
  declaration range, internal / internal-detail names - this includes private names -, aux

  extractor's `analyzeCore` assigns them (constructors included). N equals the 311,415 of
  benchmarks/results/mathlib-source-vs-printed-2026-10-04.txt.
- Sample: 5,000 without replacement (1.61% of N), partial Fisher-Yates driven by splitmix64,
  seed 20261004. Kinds in the sample: theorem 3,740, definition 640, instance 481, constructor
  67, class 42, structure 23, opaque 5, inductive 2.
- Every percentage below is of the 5,000 (measured); read as a statement about all 311,415 it is
  (extrapolated) from 1.61% of them. The bracket is a 95% Wilson score interval (it behaves at
  0; the finite-population correction, 1.6%, is ignored).

CLASSIFICATION OF THE 111 "different"
-------------------------------------
Pre-registered rules (written before the full run), applied in order, each step normalising both
prints cumulatively; the first step that makes them equal names the class:
  A  remove `✝` (+ superscript digits) and rename `inst_N` to `inst`          (hygiene)
  B  then delete `↑ ⇑ ↥`                                                       (coercion arrows)
  C  then delete `@`                                                           (explicit application marker)
  D  then replace every identifier by its last dotted component                (namespace qualification)
  E  then replace every identifier by one placeholder                          (identifier spelling, same token skeleton)
  F  otherwise                                                                 (other)
  identifier = regex [^\W\d][\w'!?.]* (Python, Unicode).
Result: A 0, B 0, C 2, D 5, E 2, F 102. Under the pre-registered rules 102 of 111 (91.9%) are
"other". D's 5: 3 reference dangling private proof auxiliaries (old `_proof_362✝`, new the
full `_private.Mathlib....0._proof_362`), 2 print `antidiagonal` with a `HasAntidiagonal.`
qualifier the old print did not have.

Post-hoc split of the 102 "other" (rules written after reading those 102, applied in order on the
whitespace-normalised prints; counted, not tuned to zero):
  F1  new has more "setOf fun" than old: set-builder {x | p} printed as (setOf fun x => p)   45   (dangling 3)
      Cause, read from v4.34.1 source: `setOf` became `@[deprecated (since := "2026-07-09")]
      alias setOf := Set.ofPred`, and the set-builder unexpanders are `@[app_unexpander Set.ofPred]`
      (Mathlib/Data/Set/Defs.lean in v4.34.1); the old Expr says `setOf`. The constant still
      exists, so it is not dangling.
  F2  new has more "↧" than old: `ModuleCat.of k X`, `TopCat.of X`, `CommRingCat.of R`, ... now
      printed with `↧X`, a notation v4.31.0 does not have (introduced in
      Mathlib/CategoryTheory/ConcreteCategory/Notation.lean; v4.31.0 Mathlib mentions `↧` only
      in its Unicode linter)                                                       16   (dangling 1)
  F3  new has more "_private." than old                                                       0   (these fell in D)
  F4  new has more "@" than old: an application printed with all arguments, e.g.
      `@Polynomial.coeff R inst p n` for `p.coeff n` - the new printer no longer elides the
      old application's arguments; read as a changed signature or instance argument (13 of the
      28 reference a dangling constant), not checked per record                              28   (dangling 13)
  F5  rest                                                                                    13   (dangling 2)
      (e.g. `∈ Finset.Ioi a` -> `> a` binder notation, `mfderivWithin` -> `mfderiv[...]`,
      `↑f` -> `OrderHomClass.toOrderHom f`, `T%`-notation expanded, structure-projection
      notation lost)
Of the 111: 24 reference a dangling constant, 87 do not.

So the drift has three shapes, and only the first one is "notation got better":
  - new notation applied to old terms (F2, some F5): arguably an improvement, still not what the
    old version printed;
  - a renamed/deprecated constant the new notation no longer recognises (F1, F4): the old
    version printed notation, the new printer prints the raw application;
  - a constant gone from the new environment: either invisible (instances, 353 of 388) or a
    visible wrong/raw print (D, F4) or no print at all (11 "print failed").

WHAT THIS DOES NOT MEASURE
--------------------------
- Only the pair v4.31.0 -> v4.34.1 (3 minor releases apart). Drift for v4.29.0 / v4.30.0 against
  v4.34.1 (5 and 4 apart) is unmeasured and must not be extrapolated from this: the causes found
  here are individual renames and refactors (setOf -> Set.ofPred dated 2026-07-09, the
  OpenPartialHomeomorph refactor, ↧), which accumulate per release and are not linear.
- It prints with plain `Meta.ppExpr` of the full type, not with the extractor's own signature
  printer (binders split off, `pp.tagAppFns`, `pp.funBinderTypes`, refs/infos, equations, fields).
- The `.olean` reader of D10 is assumed perfect: the old Expr was obtained by the old Lean itself
  and transported through a lossless serialization (0 round-trip mismatches). Misreads are not
  in these numbers.
- Only declaration types; docstrings, equations, structure fields, instance lists are not
  printed here.
- Scoped notation: no namespace is opened on either side (the extractor's default), so scoped
  notation is absent in both prints and its drift is not measured.
- "identical" is text equality after whitespace collapse; a print that is identical can still
  point a link at a constant whose meaning changed (the 353 identical-but-dangling records).
- The 5,000 are a uniform sample of declarations, not of page views.

    | .bvar i => pure (Json.arr #["b", toJson i])
    | .fvar id => do
      modify fun s => { s with fvars := s.fvars + 1 }
      pure (Json.arr #["F", nameToJson id.name])
    | .mvar id => do
      modify fun s => { s with mvars := s.mvars + 1 }
      pure (Json.arr #["M", nameToJson id.name])
    | .sort l => do pure (Json.arr #["S", toJson (← serL l)])
    | .const n ls => do
      let is ← ls.mapM serL
      pure (Json.arr #["C", nameToJson n, Json.arr (is.toArray.map toJson)])
    | .app f a => do let i ← serE f; let k ← serE a; pure (Json.arr #["A", toJson i, toJson k])
    | .lam n t b bi => do
      let i ← serE t; let k ← serE b
      pure (Json.arr #["L", nameToJson n, Json.str (biCode bi), toJson i, toJson k])
    | .forallE n t b bi => do
      let i ← serE t; let k ← serE b
      pure (Json.arr #["P", nameToJson n, Json.str (biCode bi), toJson i, toJson k])
    | .letE n t v b nd => do
      let i ← serE t; let k ← serE v; let m ← serE b
      pure (Json.arr #["E", nameToJson n, toJson i, toJson k, toJson m, toJson nd])
    | .lit (.natVal n) => pure (Json.arr #["N", Json.str (toString n)])
    | .lit (.strVal s) => pure (Json.arr #["T", Json.str s])
    | .proj s i b => do let k ← serE b; pure (Json.arr #["J", nameToJson s, toJson i, toJson k])
    | .mdata _ _ => unreachable!
  let s ← get
  let idx := s.nodes.size
  set { s with nodes := s.nodes.push j, emap := s.emap.insert (StrictE.mk e) idx }
  return idx

def serialize (e : Expr) : Json × SState :=
  let (root, s) := (serE e).run {}
  (Json.mkObj [("levels", Json.arr s.levels), ("nodes", Json.arr s.nodes), ("root", toJson root)], s)

def rebuild (j : Json) : Except String Expr := do
  let lv ← (← j.getObjVal? "levels").getArr?
  let nd ← (← j.getObjVal? "nodes").getArr?
  let root ← (← j.getObjVal? "root").getNat?
  let mut ls : Array Level := #[]
  for x in lv do
    let a ← x.getArr?
    let tag ← a[0]!.getStr?
    let l ← match tag with
      | "z" => pure Level.zero
      | "s" => do pure (Level.succ ls[← a[1]!.getNat?]!)
      | "m" => do pure (Level.max ls[← a[1]!.getNat?]! ls[← a[2]!.getNat?]!)
      | "i" => do pure (Level.imax ls[← a[1]!.getNat?]! ls[← a[2]!.getNat?]!)
      | "p" => do pure (Level.param (← jsonToName a[1]!))
      | "v" => do pure (Level.mvar ⟨← jsonToName a[1]!⟩)
      | t => throw s!"bad level tag {t}"
    ls := ls.push l
  let mut es : Array Expr := #[]
  for x in nd do
    let a ← x.getArr?
    let tag ← a[0]!.getStr?
    let ex ← match tag with
      | "b" => do pure (Expr.bvar (← a[1]!.getNat?))
      | "F" => do pure (Expr.fvar ⟨← jsonToName a[1]!⟩)
      | "M" => do pure (Expr.mvar ⟨← jsonToName a[1]!⟩)
      | "S" => do pure (Expr.sort ls[← a[1]!.getNat?]!)
      | "C" => do
        let is ← (← a[2]!.getArr?).mapM (·.getNat?)
        pure (Expr.const (← jsonToName a[1]!) (is.toList.map (ls[·]!)))
      | "A" => do pure (Expr.app es[← a[1]!.getNat?]! es[← a[2]!.getNat?]!)
      | "L" => do
        pure (Expr.lam (← jsonToName a[1]!) es[← a[3]!.getNat?]! es[← a[4]!.getNat?]!
          (codeBi (← a[2]!.getStr?)))
      | "P" => do
        pure (Expr.forallE (← jsonToName a[1]!) es[← a[3]!.getNat?]! es[← a[4]!.getNat?]!
          (codeBi (← a[2]!.getStr?)))
      | "E" => do
        pure (Expr.letE (← jsonToName a[1]!) es[← a[2]!.getNat?]! es[← a[3]!.getNat?]!
          es[← a[4]!.getNat?]! (← a[5]!.getBool?))
      | "N" => do pure (Expr.lit (.natVal (← a[1]!.getStr?).toNat!))
      | "T" => do pure (Expr.lit (.strVal (← a[1]!.getStr?)))
      | "J" => do pure (Expr.proj (← jsonToName a[1]!) (← a[2]!.getNat?) es[← a[3]!.getNat?]!)
      | t => throw s!"bad node tag {t}"
    es := es.push ex
  return es[root]!

def isProjFn (declName : Name) : MetaM Bool := do
  let env ← getEnv
  match declName with
  | .str parent name =>
    let some si := getStructureInfo? env parent | return false
    return getProjFnForField? env parent (Name.mkSimple name) == declName
      || (si.parentInfo.any fun pi => pi.projFn == declName)
  | _ => return false

def isBlackListed (declName : Name) : MetaM Bool := do
  if ← isProjFn declName then
    return false
  match ← findDeclarationRanges? declName with
  | some _ =>
    let env ← getEnv
    pure declName.isInternal
    <||> (pure <| isAuxRecursor env declName)
    <||> (pure <| isNoConfusion env declName)
    <||> (pure declName.isInternalDetail)
    <||> isRec declName
    <||> isMatcher declName
  | none => return true

def isInstanceDecl (declName : Name) : MetaM Bool := do
  return (instanceExtension.getState (← getEnv)).instanceNames.contains declName

def kindOf (name : Name) (ci : ConstantInfo) : MetaM String := do
  match ci with
  | .axiomInfo _ => return "axiom"
  | .thmInfo _ =>
    let isInst ← if ← isProjFn name then pure false else isInstanceDecl name
    return if isInst then "instance" else "theorem"
  | .opaqueInfo _ => return "opaque"
  | .defnInfo _ =>
    let isInst ← if ← isProjFn name then pure false else isInstanceDecl name
    return if isInst then "instance" else "definition"
  | .inductInfo _ =>
    let env ← getEnv
    let isStruct := isStructure env name
    let isCls := isClass env name
    return if isStruct then (if isCls then "class" else "structure")
      else (if isCls then "class_inductive" else "inductive")
  | .ctorInfo _ => return "constructor"
  | .quotInfo _ => return "opaque"
  | .recInfo _ => return "recursor"

def enumerate : MetaM (Array (Name × Name)) := do
  let env ← getEnv
  let mods := env.header.moduleNames
  let mut seen : Std.HashSet Name := {}
  let mut out : Array (Name × Name) := #[]
  for i in [0:mods.size] do
    let m := mods[i]!
    unless (`Mathlib).isPrefixOf m && m != `Mathlib do continue
    for n in env.header.moduleData[i]!.constNames do
      if seen.contains n then continue
      seen := seen.insert n
      match env.find? n with
      | none | some (.recInfo _) => continue
      | some _ => pure ()
      if ← isBlackListed n then continue
      out := out.push (n, m)
  return out

def splitmix (s : UInt64) : UInt64 × UInt64 :=
  let s := s + 0x9E3779B97F4A7C15
  let z := (s ^^^ (s >>> 30)) * 0xBF58476D1CE4E5B9
  let z := (z ^^^ (z >>> 27)) * 0x94D049BB133111EB
  (z ^^^ (z >>> 31), s)
