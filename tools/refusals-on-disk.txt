# The refusals of `litedoc4` that need something on disk, frozen.
#
# The companion of `tools/refusals.txt`, read by the same `tools/refusal-gate.sh`:
# one normaliser, one usage block, one count reconciliation across both files.
# A row here carries the fixture it is run against; the fixture is rebuilt in a
# directory of its own before every run of that row, by both arms and by
# `--mint`.
#
# **Written by `tools/refusal-gate.sh --mint --from <rust litedoc4>`**, except
# for the `@case`, fixture and `argv` lines, which are written by hand, and
# except for the `rust-differs` rows, whose bodies are written by hand from the
# Lean binary and which minting leaves alone.
#
# FORMAT — everything `tools/refusals.txt` has, plus these, all optional and all
# written before `argv`:
#   dir <relpath>       mkdir -p inside the case directory
#   file <relpath>      write a file; its body is the `>` lines that follow
#   > <text>            one line of that body. A bare `>` is an empty line and a
#                       trailing `\s` is one trailing space, as for `|`. The
#                       file ends with a newline
#   exec <relpath>      chmod +x a file this case already wrote
#   git <args...>       run git inside the case directory
#   rust-differs <why>  the Rust half words this refusal differently and the two
#                       cannot be made to agree — two independent parsers, or a
#                       defect on one side that is not fixed yet. The **lean**
#                       arm checks the row as normal; the rust arm skips it and
#                       names it in its summary; `--mint` leaves it alone. <why>
#                       is what Rust says instead, and it is required
#   stdout-not-frozen <why>
#                       this run reports progress before it refuses, so the row
#                       freezes stderr only. Required for any row that writes to
#                       stdout at all — without it the gate fails, which is what
#                       keeps the declaration from happening by accident
#
# `<varies>` inside a body line matches any text, possibly empty, at that point.
# It is for text that is not this program's — an OS `strerror`, a third-party
# parser's message — and it is written **by hand**: `--mint` keeps it and checks
# that the segments around it still match, and fails rather than replace it with
# today's text.
#
# The argv of a row names its files relatively wherever the product does not
# canonicalize them, so that the frozen message carries no absolute path.
# `<dir>` is the case's own directory, for the rows where it does.

# --- C. `--root` package files -----------------------------------------------
#
# `litedoc4 modules --root <dir>` is the cheapest reader of a lakefile; `build`
# reaches the same seven refusals when `--lib` is absent. All of them end in
# "Pass --lib <Name>". The eighth shape — no lakefile at all — needs no fixture
# and is `modules-no-lakefile` in tools/refusals.txt.

@case lakefile-lean-is-code
file root/lakefile.lean
> import Lake
> open Lake DSL
>
> package pkg
>
> lean_lib Pkg
argv modules --root root
exit 3
| litedoc4: root/lakefile.lean is Lean code, not data: `lean_lib` there is a Lake DSL command whose argument can come from an `open`ed namespace or from any Lean expression, so reading it honestly means elaborating it with Lake — which this command does not do. Pass --lib <Name> (repeatable) and the glob will use it
|

@case lakefile-no-lean-lib
file root/lakefile.toml
> name = "pkg"
argv modules --root root
exit 3
| litedoc4: root/lakefile.toml: no [[lean_lib]] block. A package with no library has no modules to document; if it has one under another spelling, pass --lib <Name>
|

@case lakefile-lean-lib-no-name
file root/lakefile.toml
> [[lean_lib]]
> leanOptions = {}
argv modules --root root
exit 3
| litedoc4: root/lakefile.toml: the [[lean_lib]] block ending at line 2 has no `name` key. Lake fills that in from the package, and inventing the value here would glob a module root nobody wrote down. Pass --lib <Name>
|

@case lakefile-lean-lib-extra
file root/lakefile.toml
> [[lean_lib.extra]]
> name = "Pkg"
argv modules --root root
exit 3
| litedoc4: root/lakefile.toml:1: `[[lean_lib.extra]]` mentions lean_lib in a spelling this does not read (only a bare `[[lean_lib]]` header is). Skipping it would document fewer libraries than the package has, silently. Pass --lib <Name>
|

@case lakefile-name-not-a-string

| litedoc4: root/lakefile.toml:2: `name = { from = "pkg" }` is a `name` this does not read — it wants `name = "<Ident>"`, one plain double-quoted string with no escapes. Pass --lib <Name>
|

@case lakefile-multiline-string
