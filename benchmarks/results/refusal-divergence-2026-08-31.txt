litedoc4 — 135 argv-only refusals, and the 17 the two halves word differently
=============================================================================

2026-08-31. Apple M1 (macOS 25.6.0). Commit fe8e100, working tree clean apart from
tools/refusal-gate.sh, tools/refusals.txt and this file.

WHY THIS WAS TAKEN
------------------
`benchmarks/results/purelean-refusal-diff-2026-08-31.txt` asked the same
question over **24 hand-picked probes** and answered "the two halves already
agree": exit codes 0/24 apart, stderr 21/24 byte-identical, the other 3 differing
only in the substrate's wording (`std::io` / `serde_json` against `IO.Error` and
Lean's own JSON parser). `.claude/purelean-plan.md` records that as M10's good
news.

This is the same question over **135 cases**, chosen to cover every subcommand's
argv refusals rather than to sample them. The answer is different, and the
difference is not substrate wording.

----------
  rust   target/release/litedoc4    `cargo build --release --bin litedoc4` at
                                    this commit; `--version` -> litedoc4 1.3.0
  lean   .lake/build/bin/litedoc4   `tools/build-lean-exe.sh --toolchain-from
                                    e2e/micro` was a no-op at this commit, so
                                    the binary is HEAD's; `--version` -> litedoc4 1.3.0
  how    tools/refusal-gate.sh over tools/refusals.txt. Both binaries are run
         with identical argv from the same empty working directory, with
         EXTRACT_BIN and TARGET_REPO unset (both stand in for a flag, so a
         machine that exports them answers four cases differently). Exit code
         taken without a pipe. stderr compared whole, after replacing the work
         directory with `<dir>` and the `--help-all` block with `<usage>` —
         one normaliser, used by both arms and by the minting.

  Scope: **command lines only**. 132 of the 135 are refused before anything on
  disk is opened; the other 3 look at two empty directories and one absent one.
  Nothing here reaches a crafted IR tree, a ledger or a `litedoc4.toml`, which
  is why none of the 3 substrate differences the 24-probe run found is in this
  set — those need a file to fail on.

WHAT THIS SETTLES
-----------------
Settles: on 135 argv refusals the two halves agree on the exit code without
exception and on `--help-all` byte for byte, and disagree on 17 messages. **The
24-probe reading — "the refusal class the handoff feared is already matched" —
does not survive at this sample size.** 8 of the 17 are the Lean half declining
to name a `crates/` path, which is a decision M10 makes correct; the direction
of convergence is therefore not the same for every group, and is a product
judgement rather than a defect to be fixed one way.

Does not settle: 135 argv cases are not the 93 entrance refusals `#[test]`
holds, and the second tranche — anything needing a crafted IR tree, a ledger, a
`litedoc4.toml` or an on-disk module list — is untouched here.
`impact --mode <nonsense>` is deliberately in that tranche: the mode is
consulted only when there is something to select, so with no IR tree the run
fails on the tree instead.

--- frozen
litedoc4: --serve-dir is not offered: `--serve` starts a server this run owns, and a server it does not own is one whose olean generation it cannot vouch for. Correctness comes from that generation and never from the round number — a server imported before the edit returns the pre-edit owner of every name that moved, and then no round is safe, including round 2 (measured, stage 6a). See `crates/litedoc4/src/resident.rs`
