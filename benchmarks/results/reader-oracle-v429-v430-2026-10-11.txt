What the oracle compares now
----------------------------
The oracle text (OleanReader/Serialize.lean, written by both sides) gained three kinds of line,
because without them two of the three record facts above can be wrong with every line still equal:
  layout Lean.Meta.SimpTheorem.mk <objs> <scalar bytes>
      the writer: `Compiler.LCNF.getCtorLayout`; the reader: its record. Needed because the decoder's
      own size check cannot tell 3 scalars from 4: align8(8 + 5*8 + 3) = align8(8 + 5*8 + 4) = 56, and
      the padding byte is zero, so a 4-flag decoder reads v4.30.0 data as `backwardRfl = false` and a
      3-flag decoder reads v4.31.0+ data without error (both measured below).
  ns <module> <name>
      every module's namespace entries in stored order; the writer takes them from its own extension
      whose name ends in `namespacesExt`, whatever it registers it as.
  simp <module> <scope> <entry>
      every simpExtension entry: origin, priority, post, perm, rfl, key count, level params, proof.
      backwardRfl cannot be in the shared text (v4.29/v4.30 cannot name the field); the layout line
      is what holds it.
And the oracle item also asks the reader to take the Dump.olean that the writer's own `lean`
compiled (`reader header <file>`): it must name that writer's record. Without it the 4.29.1 header
split would be checked on the core side only.
To build on v4.29/v4.30, Serialize.lean's `unfoldMask` calls `Meta.canUnfold` under
`withTransparency` instead of `Meta.canUnfoldDefault`, which is private before v4.31.0 (the same
answer on every writer: the `status` lines are equal on all eight answered toolchains).

                                 (the runs above: refuse-version ok); with the swap under the final
                                 order, `reader header` on that Dump.olean exits 1 ("... a different
                                 build of 4.29.1 is refused") and the core still reads as 4.29.0.

What this does not cover
------------------------
  - Core only. No Mathlib, and no package compiled by v4.29.x or v4.30.0 other than the gate's
    Dump.olean and a one-line Foo.lean, was read in this work.
  - `backwardRfl = true` values: the shared text cannot carry the field, so a v4.31.0+ entry with
    it set is held only through the layout line, not value by value.
