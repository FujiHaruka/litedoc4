M, one version natively: the render scans each module and drops it, then parses it again for its page
====================================================================================================

Conditions: Apple M1, 16 GB, macOS 26.6.2; Lean v4.33.1, Mathlib v4.33.1 (0df444a360); the M slice
(438 modules). Same checkout and store entry as mv-m-parallel-render-2026-10-12.txt. litedoc4 at
8c57984 (base) and 8c57984 + this change (new), both built with Lean v4.31.0; one prebuilt extractor
in every build arm. Warm (a discarded warm-up per binary). One run per arm (the user's rule for
levers: one run, +-10% accepted). Units: MB = 10^6 B.

Where the render's memory was, before (measured, `store render` one worker, a scratch build with
a footprint marker at each stage and, in a separate run, a walker counting bytes reachable from
each structure)
  stage                          footprint MB   live data
  store read returns               78.9         compressed entry 4.6, inflated pack 30.1, per-file
                                                copies 30.2 (copies: the three add up exactly)
  all modules parsed              178.7         parsed module IRs 111.4
  input built                     222.2         97% of the peak; link index 18.8
  cross-module tables built       227.3         143.2 live
  pages built                     229.0         159.5 live (the parsed modules still held)
  data and pages written          229.9
  peak footprint                  229.5 (no markers)
  Dropping each module's bytes as it is parsed: 224.8 MB (-2%). Keeping the per-file copies alive
  to the end: 256.1 MB (+26.6): today they are already freed when the input is built.

The change: the render input carries one loader per module instead of the parsed modules. Pass 1
(on --jobs workers) parses a module, keeps its facts, its declaration names and refs, and its member
names, and drops it; the name index and the suppressed set are built from those, in module order.
Pass 2 (on the workers) parses each page module again and builds its page. No moment holds every
parsed module. The per-file bytes stay for the re-parse.
