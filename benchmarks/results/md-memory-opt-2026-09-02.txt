=== 1  WHAT LAKE ACTUALLY PASSES

Not read off lakefile.lean but off the command Lake ran, with `lake build -v` in
the one-line workspace tools/build-lean-exe.sh writes under .lake/host, after
deleting .lake/build/md4c.o so the job could not be replayed.

  clang -c -o .lake/build/md4c.o vendor/md4c/md4c.c \
    -I <toolchain>/include -I vendor/md4c -fPIC \
    -Werror=implicit-function-declaration \
    -I <toolchain>/include/clang -I csrc/libc

  (the same for csrc/md_events.c -> md_events.o)

  No -O of any kind. clang's default is -O0, so that is the level every byte of
  md4c and md_events that ships is compiled at. The gate compiled at -O1.

=== 2  THE READER, AND ITS TWO REFUSALS

`PRODUCT_OPT` comes out of lakefile.lean's `ccFlags`. Each case is a copy of the
tree with only lakefile.lean replaced; everything else is the working tree.

  ccFlags renamed away               exit 2   md-memory-gate: lakefile.lean no longer defines ccFlags -- that function is what the product's C
  ccFlags naming two levels          exit 2   md-memory-gate: ccFlags names 2 optimisation levels (-O2, -O1) -- which one reaches md4c.c depen
  ccFlags naming exactly one         exit 2   taken: -O2
  the tree as it stands              exit 2   taken: (none)

  The last two rows are the same exit 2 for a different reason: on this machine a
  program built with -fsanitize=address never reaches its own main, so the gate
  refuses after reading the level. The message on line 1 is what separates them.

=== 4  THE SECONDS, AND WHY THEY ARE NOT A COMPARISON

The step took 3.09 s here (12:25:56.525 -> 12:25:59.612). The same gate at -O1
took 5.38 s in the run immediately before it (job 100243391400, 12:16:11.013 ->
12:16:16.391) and 6.6 s in benchmarks/results/md-memory-gate-2026-09-02.txt.

**Three single runs on three runner instances.** 5.38 and 6.6 are the same code
at the same level, so the spread between them is the noise floor, and 3.09 sits
inside a range that noise alone reaches. Do not read it as a speedup: nothing
here was measured under controlled conditions, and the change was not made for
time. What is being recorded is that the gate did not get slower enough to
matter -- eight compiles at -O0 rather than -O1, six links, six runs.
