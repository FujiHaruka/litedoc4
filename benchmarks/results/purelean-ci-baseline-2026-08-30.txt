pure-Lean replacement study — what the Rust half costs in CI today
=================================================================
2026-08-30

WHAT THIS MEASURES
  The other half of the question. Replacing Rust with Lean removes a binary
  download and adds a Lean compile, and only CI can say which is bigger. This
  file records what the Rust arrangement costs today, on the real target, so a
  pure-Lean run has something to be measured against.

  Nothing here is about a pure-Lean build: it does not exist yet. These are
  baseline numbers (measured), read out of a run that already happened.

WHAT THIS SETTLES
  **The Rust half costs 2.9 s of CI wall clock on a cache-cold run** — one
  download of a static musl binary, plus a checksum. It is not the cargo build:
  that path exists (`cargo build --release`, no release asset for the platform)
  but did not run here, and does not run on any of the three released triples.

  **A pure-Lean renderer would replace that 2.9 s with a Lean compile.** The only
  Lean compile in this run is the extractor: 3,174 lines in 20.2 s on this
  runner (measured). At that rate the Rust half's ~10,500 lines of renderer and
  incremental logic (7,004 + 3,443, excluding tests) is (extrapolated) about
  60 s, and the extrapolation is weak in both directions — Lean compile time is
  not linear in lines, and a renderer is not shaped like an extractor. **It has
  to be measured on the real thing.**

  Both sides are cached on (toolchain + sources), so this cost is paid when the
  litedoc4 version moves, when the toolchain moves, or when the cache expires
  (GitHub evicts after 7 days of no reads). `docs.yml` runs on tag pushes, and
  the six runs before this one are 144-182 s apart from two cold ones at 941 s
  and 1,142 s — so on this repository the cache is missed more often than hit.

WHAT THIS DOES NOT SETTLE
  - the pure-Lean compile time (nothing to compile yet);
  - whether the renderer's Lean sources can share the extractor's cache entry
    (they can be in the same lake package, which would make it one build);
  - the `lake build` path for a consumer who is not using the action.
