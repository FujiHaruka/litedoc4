modules could carry a one-line description by reading `.lean` files. This is the
same question answered by the pipeline instead: extractor -> IR -> facts ->
front page, on the 422-module target, published.

## Prediction against result

The source scan found **390** `.lean` files under `InformationTheory/` opening
their first `/-! … -/` block with a `# ` heading, out of 421 files. The build
reports **390** descriptions out of 422 modules. The two agree exactly, and the
one-module difference in the denominator is the root `InformationTheory.lean`,
which the scan's directory walk did not reach and which carries no heading.

`0 repeat the module name` is the second number the build prints, and this is
the first corpus it has been read on: no module of the target heads its
docstring with its own last name component. The source scan had said the same
(0 of 390), so nothing here is new information about the target — what is new is
that the count derived through the pipeline agrees with the count derived from
the text.

The 35 descriptions carrying `<code>` are the reason the front page renders
inline Markdown rather than escaping the heading as plain text: those rows would
otherwise show their backticks.
