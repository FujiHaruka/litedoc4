### いま効いている不整合 — README は「出していない製品」を書いている

`v0.1.4` のツリーには `watch.rs` / `cli.rs` / `queries.rs` / `stages.rs` / `ledger.rs` /

つまり **README が節を割いて説明している次のものは、どのリリースにも入っていない**:

- `litedoc4 watch` + ローカルサーバ

**それでいて README は `@v0.1.4` に固定しろと案内している。**
README の言うとおりに固定した利用者は、README に書いてある機能を持たないバイナリを手にする。
**これは v1 の話ではなく、今日壊れている。**

## 2. Approach — v1 の定義を「約束とその番人」に置く

v0.1 は「**ここまでを通した線**」だった (ゲート A/B の決着だけが根拠で、未検証項目は残した)。
v1 を同じ形で引くと「機能が増えた線」にしかならない。**そうしない。**

> **v1 = 作者以外が、作者の助けなしに、使い続けられる。**

「使える」ではなく「**使い続けられる**」に置くのが要点で、そこから 4 つの約束が出る。
**約束はそれを守るゲートを伴うものだけ書く** — 守れない約束を README に書くのは、
このリポジトリが 2026-08-17 以来ずっと潰してきた「見ていないのに緑」と同じ形だから。

| | 約束 | それを守るもの |
|---|---|---|
| **P1** | **出したものが README と一致する** | リリース手順そのもの。§3 A |
| **P2** | **1.x の間に何が動かないかが宣言されている** | 宣言が先。§3 B |
| **P3** | **その宣言は一度きりの実測ではなくゲートが守る** | §3 C |
| **P4** | **外から使われる経路が一度は通っている** | §3 D |

**この分け方を選ぶ理由**: A〜D はどれも「機能を足す」話ではない。
v1 に足りないものは機能ではなく、**機能が来年も同じ意味を持ち続ける仕組み**だから。
doc-gen4 の要望 8 件は 2026-08-22 に全件決着しており、**範囲外にしたもの**
(型検索 / LeanInk 的ソース閲覧 / 依存込み全文検索 / Verso 追随) は v1 でも範囲外のまま。

**撤退ライン**: §3 B で「約束を書けるものが 1 つも無い」に着地したら、それは
v1 を名乗る条件が揃っていないということなので、**版を 0.2.0 のまま出して v1 を先送りする**。
番号を先に決めて中身を合わせにいかない。

### D — 外から使われる経路 (v1 の意味そのもの)

- [ ] **D1. R5「他人のリポジトリから `uses:` される」の保留を、v1 の定義の下で判断し直す。**
      2026-08-22 に**保留と決めた**【ユーザー判断】。そのとき記録された切り分けは:
      **覆われている** = `ci-action.yml` の `published` job が
      `uses: FujiHaruka/litedoc4@main` を実行しており、GitHub が `_actions/` へ
      checkout する実チャネルを通っている。
      **覆われていない** = **`GITHUB_WORKSPACE` が litedoc4 自身の checkout であること** —
      `action.yml` が litedoc4 のファイルが workspace に在ることに暗黙に依存していても通る
      (`hashFiles()` の glob / 相対パス / `--lib` の見つけ方)。
      **安い道は既に見つかっている** — 既存の public な Lean パッケージ (例: `batteries`、
      この木で第 2 対象として実走実績あり) を `actions/checkout` の `repository:` で
      workspace に入れるだけで、**新しいリポジトリの作成は要らない**。
      **v1 = 作者以外が使える、と定義するなら、ここは保留のままにできない**
- [ ] **D2. 受け口。** issue は有効だが **Discussions は無効**、issue テンプレート無し、
      `CONTRIBUTING` / `SECURITY` 無し。報告に要る情報は既に製品側が出している
      (`binary-source` / `timings` / `work` 行 / Lean 版) ので、
      **テンプレートはそれを貼らせる形**にすれば足りる

   B〜D の決着を待たせる理由が無い。1.0.0 はそのあとで名乗る
2. **D1 の保留を解くか** — 解かないなら、v1 の定義から「作者以外が使える」を外すことになる
