watch-gate.sh on e2e/micro — the gate that said it needed the measurement target

WHAT THIS IS
  tools/watch-gate.sh's header said it was a gate because it needs the
  measurement target, that target's toolchain and the 171 MB Mathlib
  extractor. Every one of those is an argument. This is the same gate,
  unchanged, pointed at e2e/micro: Lean core only, ten modules, no Mathlib.
  It is now .github/workflows/ci.yml's e2e-micro job, on every push.

COMMAND
  LITEDOC4=target/debug/litedoc4 \
  EXTRACT_BIN=e2e/micro/.lake/e2e-extract/extract \
  tools/watch-gate.sh --out <tmp> --target $REPO/e2e/micro --lib Micro \
    --module Micro.Unicode --other Micro.Notation

  The extractor is the one tools/e2e-micro.sh builds inside the fixture's own
  Lean environment (its step 2). litedoc4 is the debug binary, which is what
  the e2e-micro job already builds.

NOTHING UNDER --target IS WRITTEN. 'module M changed' is injected into this
  run's own copy of the ledger with `litedoc4 ledger touch`. git status was
  clean after all three runs below.

CONDITIONS
  Darwin 25.6.0 arm64 / Apple M1 / 16 GB, Lean v4.31.0, extractor built by
  tools/e2e-micro.sh, litedoc4 built debug, --jobs 4. Another cargo build was
  running on the machine at the same time.

WHAT IT COSTS, AND WHAT THAT NUMBER IS WORTH
  Two green runs the same way: real 4.02 s and real 6.11 s. **That spread is
  the point** — this is wall clock on a shared machine, and the gate asserts on
  none of it (its own header: "THE ASSERTIONS ARE INTEGERS. NOT ONE OF THEM IS A
  DURATION"). What it is for is deciding whether the gate belongs in a job that
  already takes minutes: seconds, so yes.
