doc-gen4 on the docstring links that are dead in litedoc4's Mathlib site (issue #7)
Checked 2026-10-03 from macOS Darwin 25.6, Apple M1, /usr/bin/curl 8.7.1.

Question: mathlib-render-2026-10-03.txt §4 found 51 dead internal links (24 distinct
destinations) in litedoc4's site for Mathlib fabf563a7c. What does doc-gen4 emit for the
same docstrings?

1. What the source says
-----------------------
  extendLink: "##" → name lookup; "#" or "http" prefix → unchanged; anything else →
  root ++ s. Same rule as litedoc4's extendLink.
  A link destination is a bibliography item only when it is written
  "references.html#ref_<key>" (findBibitem? href "references.html#ref_").
  A bare key as destination, "[Geck](Geck2017)", is not looked up: it is rebased.
  Citations are found by findAllReferences, which scans for "[<key>]" and appends
  "[<key>]: references.html#ref_<key>" definitions to the Markdown before parsing, so
  "[Key]" and "[text][Key]" become links to references.html. No warning is emitted on
  any path.

Commands
--------
  gh api repos/leanprover/doc-gen4/contents/DocGen4/Output/DocString.lean \
    -H 'Accept: application/vnd.github.raw'
  B=https://leanprover-community.github.io/mathlib4_docs
  curl -s $B/<module>.html | rg -o '<a [^>]*>[^<]*Geck[^<]*</a>'
  curl -s -o /dev/null -w '%{http_code}\n' <url>
  rg -o '^@\w+\{\s*([^,]+),' --replace '$1' docs/references.bib | sort -u > bibkeys.txt
  rg -o --no-filename '\[[A-Za-z][A-Za-z0-9_:+.-]*\]' Mathlib | tr -d '[]' \
    | rg -x -F -f bibkeys.txt -c
  rg -o --no-filename '\]\(([A-Za-z][A-Za-z0-9_:+.-]*)\)' --replace '$1' Mathlib \
    | rg -x -F -f bibkeys.txt | sort | uniq -c
