## 3. Approach — 3 つの束

**同じ作業を 2 回やらないための分割。** (1) IR schema を上げる変更をまとめ、
**schema 4 → 5 を 1 回だけ**にする。(2) 描画の凍結フィクスチャを壊す変更をまとめ、
**再凍結を 1 回**にする (`crates/litedoc4-render/tests/data/*-expected.json` は
プロトタイプとの byte 一致を凍結したもので、HTML を 1 バイト変えると全部落ちる)。

| 束 | 項目 | 性質 |
|---|---|---|
| **A** | b, g | 既定の HTML を動かさない。単独で出せる |
| **B** | c, e-抽出, f-抽出 | IR schema 4 → 5。後方互換に足すだけ |
| **C** | a, d, **c-描画**, e-描画, f-描画, i, 再凍結 | HTML が変わる。最後に 1 回再凍結 |

各項目に必ず 3 点を付けた。**付かないものは入れない**: (1) 落ちたときに何が壊れたか
1 行で言えるゲートかテスト (新しいゲートは**必ず一度落としてから**通す)、
(2) 撤退ライン、(3) 数字を動かすなら実測ログ。

### 凍結フィクスチャの扱い【決定 1】

`*-expected.json` は**移設の証拠**として凍結されていた。移設は M1〜M8 で完了しており、
新機能で出力が変わるのは当然なので、束 C で役割を
**「移設の証拠」から「自分の出力に対する回帰基準」へ 1 回だけ切り替えた**。
**JSON を手で編集しない** (PROVENANCE.md の禁止事項) ので、手順は
(1) 再生成手段を HEAD に置く → **`LITEDOC4_BLESS=1 cargo test`**、
(2) 差分を全件レビューし、**説明できない差分が 1 つでもあれば止める**、
(3) PROVENANCE.md を書き換える。

**`docgen4-linked-expected.json` は今も別扱い** — これは doc-gen4 の出力が期待値なので、
**触るなら doc-gen4 側の oracle (`tests/oracle/dump-html-linked.lean`) を回して取り直す**。
こちらの出力で上書きしない。

### A-1 (b) 依存宣言のリンク先を選べるようにする

**母数**: 外部リンクは 527 宣言 (Mathlib 396 + Init 130 + Lean 1)、2 か月 pin で死にリンク
**0/396**【実測】、12 か月 pin での期待値 **10.3/396**【外挿】、宣言表は gzip 5.7 MB【実測】
→ `benchmarks/results/deps-link-rot-2026-08-19.txt`。実装の数字は
`benchmarks/results/deps-docs-2026-08-19.txt`。

- **CLI**: `--deps-docs-url <Root>=<url>` / `--deps-docs-index <Root>=<url|path>` (repeatable)。
  **どちらも渡さなければ今の挙動** (版固定 GitHub ソース)。`build` が解決結果を
  `<out>/work/deps-docs-map.json` に書き、他のコマンドは `--deps-docs-map` で読む (再導出させない)。
- **規則は 1 本**: 宣言表を引けたら**名前が表に在るものだけ** docs へ、無いものはソースへ。
  表が引けなければ**全部ソース**。「あれば docs、無ければソース」というフォールバックではなく、
  **検証の結果に従うという 1 本のルール**。判断箇所は
  `crates/litedoc4-render/src/autolink.rs` の `NameIndex::link_to` **だけ**。
- **描画キーは「解決した entry」を hash する。表のバイト列ではない。**
  帰結: 新しく参照し始めた依存名が現れた最初のビルドで digest が動き、全ページを描き直す
  (Lean は走らない)。表のバイト列を hash する案だと、その名前はページが他の理由で
  触られるまでソースを指したままになる。**うるさい方を採った。**
- **`--deps-docs-map` は描画する経路と描画キーを計算する経路の全部に置いた** —
  `site` / `render` / `incremental` / `ledger build` / `ledger check` / `links`。
  描画側だけに置くと `ledger` が地図を見られず、**「変わった / 変わっていない」を
  真でない理由で答える**。付け方は 1 本 (`with_dependency_docs`)。
- **`curl` に丸投げする**。HTTP クレートを足さない。**`curl` の終了コードを
  パーサのエラーより先に読む** (失敗した取得は空 body を返すので、パーサが先に
  「JSON ではない」と言う — 真だが無用)。取得は `--max-time 120` で打ち切る。
- **ゲート `tools/deps-docs-gate.sh` は規則の両枝を見る。**
  枝 1 (docs へ行った名前) は**アンカーまで**見る — ページだけ見ると
  **生きているモジュールの中で改名された宣言**を通す。判定は宣言表ではなく
  **サーバが返した HTML の `id` 属性**に対して行う (表と突き合わせると
  「解決器が表を正しく写したか」を「リンクが生きているか」と言い換えることになる)。
  枝 2 (ソースに落ちた名前) は、その docs ページを指す href が**サイトのどこにも無いこと**を見る。
  **既定で Init も docs に向ける** — この対象で fallback が発火する唯一の root で、
  Mathlib だけだと枝 2 が空のまま「ok」と言うゲートになる【実測】。
- **撤退ライン**: 宣言表の形式が変わって読めない → **推測しない**。形を検査して違えば拒否し、
  全部ソースに落ちる。**ハングさせない** (拾った要望の 1 つが #404「ハングする」なので、
  直しがハングを足したら本末転倒)。

### A-2 (g) `watch` + ローカルサーバ

**根拠**: #389「Rust の docs はミリ秒で建つのに」/ #404「10 分ハングに見えた」。
litedoc4 は no-op 再ビルド 0.31 s / 1 宣言追加 4.35 s を既に出しており、
**足りないのはファイル監視と HTTP サーバだけ**だった。実測は
`benchmarks/results/watch-2026-08-21.txt`。

- **`lake build` はしない**【判断】。建てるのは利用者/action、litedoc4 は olean を読むだけ、
  という分担を watch でも変えない。
- **常駐 extractor はパスをまたいで生き残らない**【実測 → `resident.rs` の見出し】。
  計画は「常駐しているので 2 回目以降は環境ロードを払わない」と書いていたが**誤り** —
  Lean は import 済み環境からモジュールを差し替えられない。そして**パスが抽出するのは
  olean が動いたときだけ**なので、持ち越したサーバは定義上「いま stale になった環境を
  抱えたサーバ」になる。常駐が買っているものは**1 パスの中**の ownership/merge ラウンドが
  1 回の import を共有すること。
- **監視はタイマーで ledger に訊く。`notify` は入れなかった。** ポーリングは
  フォールバックではなく**唯一の経路**として選んだ: (1) イベントは所詮ヒントで答えは
  ledger が出す、(2) 対象 422 モジュール (olean 228 MB) の 1 回の `check_ledger` が
  **warm 0.13 s / cold 0.37 s**【実測】。既定 `--interval` 1000 ms、下限 100 ms。
- **watch は `build` をループしているだけ**。パーサ 1 本 / `Request` 1 個 /
  各パスは `build::run`。**2 本目の「サイトを建てる経路」を作らない。**
- **1 インターバルの静けさを待ってから抽出する。** `lake build` が olean を書いている
  最中に抽出すると、半分ずつ 2 つの世界からできたサイトになる。
  **待っている間は何を待っているか毎回言う** (#404 の形)。
- **失敗したパスは、世界がもう一度動くまで再試行しない** (毎秒 3 GB の import をやり直さない)。
  ただし**最初のパスの失敗は致命**。
- **`--deps-docs-url` / `--deps-docs-index` は watch では名指しで拒否**。A-1 の解決は
  「その run の IR に対して 5.7 MB の表を 1 回引く」なので、ループは「毎回引く」か
  「古いまま使う」しか選べない。
- **`--lib` と `--source-url` は起動時に 1 回だけ確定させる。** どちらも renderKey の入力で、
  トリガ側と実行側が別々に導出すると毎パス全描画になる。帰結: **セッション中の
  `git commit` はページのソースリンクを動かさない** (watch を再起動する)。
- **サーバは生成物をそのまま返す** (`crates/litedoc4/src/httpd.rs`、std だけ)。
  live-reload スクリプトは注入しない【判断】 — 見ているものと publish するものが
  別ファイルになるため。代わりに `Cache-Control: no-store`。既定ポート **8484**、
  127.0.0.1 のみ、**塞がっていたら名前を出して拒否 (次の空きに移らない)**。
- **ゲート `tools/watch-gate.sh` は olean を触らない** (`touch` は mtime しか動かさず
  ledger は内容を hash する。olean の書き換えは計測対象への書き込みで禁止)。
  `litedoc4 ledger touch` で ledger 側に注入し、`modulesExtracted` / `pagesRendered` /
  `extractorRequests` = 1/1/1 と **render-set がその名前 1 件であること**、
  **`impact` が選んだページ数と renderer が書いたページ数の一致**を見る。
  **一度落とす方法は 2 つ**: `--inject wrong-module` (1/1/1 は緑のままで名前の照合だけが捕まえる) と
  `--inject no-touch`。**壁時計でゲートしない。**
- **ゲートは「他の watch が居たら始めない」**【実測 2026-08-21】。`watch` は起動した
  シェルより長生きするので、取り残しが同じ作業領域を掴む。すると (1) ゲートのビルドが
  読んでいる IR を書き換えて `EOF while parsing a value at line 1 column 0` になり
  (**IR の書き換えは atomic ではない** → §8)、(2) 後始末の削除中にファイルを作り直して
  `rm: Directory not empty` になる。**どちらも「ゲートが壊れている」ように見える。**
  → pid を名指しして **exit 2 で拒否する。殺さない。** **拒否した作業領域は消さない**
  (拒否経路の `rm -rf` が他のプロセスの使うディレクトリを実際に消した【実測】)。
- **撤退ライン**: idle パスが interval の 1 割を超える → `--interval` の既定を上げ、
  それでも足りなければ `notify` 1 本を入れ**ポーリングは消す** (2 本にしない)。

### B-1 (c) `sorry` / `sorryAx` 依存の可視化

**根拠**: #270 (open, 2025-03)。「形式化途中のプロジェクトでは欲しい」と書かれていて、
**その利用者層が litedoc4 の対象そのもの**。実測は `benchmarks/results/sorry-2026-08-21.txt`。

- **IR は `sorry: "direct" | "transitive"` の 2 値、無ければキーごと省略**【決定 2】。
  Mathlib 依存の宣言はほぼ全部が `Classical.choice` / `propext` / `Quot.sound` を持つので、
  公理の全列挙は情報量が無いのに IR を太らせる。**全列挙の価値は未検証項目** (§8)。
- **`collectAxioms` は推移閉包を歩かない。撤退ライン (+10%) は発火せず既定オン。**
  Lean は `exportedAxiomsExt` を持ち、**宣言ごとの公理配列は olean を書くときに計算済み**。
  import された定数への `collectAxioms` はその配列への binary search で、式を 1 つも歩かない。
  v4.31.0 / v4.32.2 / v4.33.0 で同一実装。対象 422 モジュール / 4,584 宣言で
  **phase 0.006 s = `total` 5.916 s の 0.10%**【実測、warm、交互 5 対】。
- **`"direct"` の判定だけが式を歩くので、答えが `"direct"` になり得るときしか訊かない。**
  **費用はパッケージの大きさではなく汚染された宣言数に比例する。**
  **天井を測ってある**: 早期脱出を外して全宣言で式を歩かせると **0.594 s = +10.0%**
  【実測、使い捨てバイナリ、IR は製品版とバイト一致】。**撤退ラインちょうど**なので、
  早期脱出は最適化ではなく設計の一部。
- **対象パッケージには `sorry` が 1 件も無い** (0 direct / 0 transitive)【実測】。
  上の 0.10% は**安い側しか測っていない**。分類が実際に汚染宣言で動くことは
  `e2e/micro` が持つ (1 direct / 1 transitive)。
- **ablation は `--no-sorry`** (`--axioms` の opt-in ではない)。2 本の腕が**同じバイナリ**で
  なければ差は取れないので、既存の `--no-attrs` と同じ形にした。
- **`sorry` の計算は解析ループの後の単独パス、シングルスレッド** (`--jobs` が答えに
  届かないことがバイト一致の条件)。
- ゲートは `tools/e2e-micro.sh` の **GATE 7**。入力は `Micro/Sorry.lean`
  (`Micro/Basic.lean` ではない — GATE 6 があのファイルに probe を追記する)。
  **比較した本数を数え**、加えて**他の宣言が `sorry` を名乗っていないこと**を見る —
  全部に `"transitive"` を返す分類器は肯定側 2 件を通ってしまう。

### B-2 (e) 属性の構造化

**根拠**: #331 (open)「`@[stacks 07BJ]` が docs に出ない」。
実測は `benchmarks/results/attrs-2026-08-21.txt`。

- **線の形は `Ref` に倣った 2 要素配列 `[name, value]`**。オブジェクトを作らない。
  Rust 側は**両方の形を受ける** — 裸の文字列 (schema 4) と 2 要素配列。
  **要素数が違う配列は拒否**する。
- **分割は extractor でやる。描画側で再分割しない。** 連結を作っているのは extractor で、
  境界を知っているのはそこだけ。実際 `deprecated` の値には空白・括弧・引用符が、
  `specialize` の値には角括弧が入る。**対象にはその形が 1 つも無い**
  (163 出現 / 6 種類でほぼ全部が裸の名前【実測】) ので、
  `e2e/micro/Micro/Attrs.lean` が唯一の検査場所。
- **IR の増分は +814 B / 15,093,293 B = +0.0054%**【実測】。
- **描画は 1 バイトも動かしていない** — `Attr::text` が 2 要素を schema 4 の連結に戻す。
  値に対して何かする (`@[deprecated Foo]` を `Foo` へのリンクにする) のは束 C。
- ゲート **GATE 8** は各宣言の `attrs` を丸ごと比べ、**実際に比較できた期待の本数**と
  **他の宣言が同じ属性を主張していない本数**も数える (positive な期待だけでは
  「全部に色を付ける分類器」を捕まえられない)。一度落とした実測: `specialize` の
  name/value 境界を 1 つずらすと **exit 1** で両側を名指しする。
- **`@[stacks]` そのものは閉じていない** — §8 を見よ。**#331 が閉じるとは書かない。**

### B-3 (f) 自動生成宣言の由来

**B-0 の調査で前提が崩れたので書き直した**【実測 2026-08-21 →
`docs/plans/b0-generated-decls.md`】。**旧版の想定は 2 つとも誤りだった:**
(1)「`(line, col)` を共有する群を親子とみなせる」→ **みなせない**。`declRange` は
生成された宣言に**それを生成した属性トークンの位置**を与える (指すのは生成器であって親ではない)。
候補規則 5 つを Mathlib 標本 (10 モジュール / 2,786 宣言 / 144 群) で試して全部落ちた —
「親が群の中に居る」は **0 / 144**、**47 群は 2 つ以上の名前空間にまたがる**。
(2)「#163 の症状 = 生成宣言が本体より前に出る」→ **両標本で 0 件**。
実際の症状は**「親から離れて、無関係な宣言のブロックの中に落ちる」** (Mathlib 標本 188 / 224)。
**旧版のまま実装すると、直すべき入力が 1 件も無いまま緑になるゲートを作る。**

実測は `benchmarks/results/generated-decls-2026-08-21.txt`。

- **structure の projection (#184) はやることが無い** — IR に在り、190 件すべてが
  トップレベル宣言として存在し、`Suppressed::of_site` が単独ページを消すだけで

### `RENDERER_ID` は別の互換トークン【2026-08-22】

`litedoc4_incr::RENDERER_ID` は「今このページを描き直したらバイトが変わるか」を答えるもので、
**IR が動かなくても描画が動けば上げる**。束 C は 3 つとも描画を動かすので **v2 → v3**。
**上げ忘れたときの壊れ方が静か**なのが要点: v2 が描いたサイトの上で増分ビルドを回すと、
**全ページが最新だと判定されて古いバイトが残る**。出力は「0 pages rendered」で成功に見える。

### ゲートを「走らせなかった」と言えるようにした

版を上げると `v0.2.0` の資産は存在せず、項目 1・2 は**ダウンロードを実行できない**。
`ok` は「走らせていない枝に緑を出すゲート」、`FAILED` は「壊れていない機構を壊れたと言う」。
どちらも嘘なので**世界を 3 つに分けた**:

| 判定 | 条件 | 項目 1・2 |
|---|---|---|
| Release がある | 資産 URL が **200** | 今までどおり: 取得・検証・キャッシュ |
| Release が無い | 資産 URL が **404** | **文書化された落ち方**: 段 3 が資産の不在を告げ、PATH が答え、サイトが書かれ、キャッシュには何も残らない |
| 訊けない | curl が非ゼロ / 200 でも 404 でもない | **exit 2**。オフラインは第 3 の世界ではなく、このゲートの失敗 |

- 判定は**最初に 1 回**。`curl -sSL --head -w '%{http_code}'` で **`-f` は使わない** —
  `-f` を付けると 404 が curl の終了コードに化けて、区別したかった 1 点が消える。
- 項目 2 は**鏡像**にした: Release があれば「2 回目は curl を呼んではいけない」、
  無ければ「項目 1 が何もキャッシュしていないので **curl を呼ばなければならない**」。
- **要約と最終行の両方**が `NOT EXERCISED` と言う。緑の最後の 1 行しか読まない者にも、
  どちらの世界だったかが伝わる必要がある。

**実測 (2026-08-21、Apple M1 / macOS 26.0 / Lean v4.31.0)**:
Release の**無い**世界 (`0.2.0`) → **5 項目すべて緑、exit 0** で最終行に
`(items 1 and 2 not exercised — …)` /
**一度落とす** (項目 1 の PATH から `pathbin` を外す) → **exit 1** /
Release の**ある**世界 (`Cargo.toml` を一時的に `0.1.4` に戻す) →
**項目 1・2 が実際にダウンロードして落ちる**、exit 1。
**3 行目が欠陥の再現**であり、同時に「200 側の枝は選ばれ、実際に走る」ことの証拠
(取得も検証もキャッシュも成功したうえで `unknown field selectionRange` で落ちる)。
**CI が名指ししたのは `attrs` (B-2)、ここで名指しされたのは `selectionRange` (B-3)** —
同じ非互換で、パーサが**先に当たったフィールド**が違うだけ。
**片方を直せば済むという意味には読まない。**
`0.2.0` を名乗る木では 200 側は通らないので、**この枝が CI で走るのは次に tag を打ったとき**
(`ci-lake.yml` の `download` ジョブ)。
