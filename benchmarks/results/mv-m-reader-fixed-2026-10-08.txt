DEFECT 1: THE MANUAL ROOT, NOW ASKED OF THE OLD LEAN
  Cause: Lean/DocString/Links.lean (identical in v4.31.0 .. v4.34.1) has
    builtin_initialize manualRoot : String ← (LEAN_MANUAL_ROOT if set, else the executable's
      pre-configured getManualRoot (), else https://lean-lang.org/doc/reference/latest/, plus "/")
  and Lean/DocString.lean:44 applies rewriteManualLinks when a docstring is looked up, so the
  running Lean's root (4.34.1) was written into an old version's docstrings.
  Fix (reader extract, the one place every caller goes through): the toolchain whose
  Init/Prelude.olean the --old search path resolves is the old Lean; its bin/lean runs
    import Lean.DocString.Links
    #eval IO.println s!"{Lean.githash} {Lean.manualRoot}"

  user's LEAN_MANUAL_ROOT is honoured as the native run honours it). If its root differs from the
  running Lean's, reader extract runs itself again with LEAN_MANUAL_ROOT set to the answer (a
  builtin_initialize is fixed at process start); the run asks again and finds them equal. Its
  githash must equal the githash the oleans were written by. Any failure to ask, a githash
  mismatch, or a root still differing under that LEAN_MANUAL_ROOT is a refusal by name.

DEFECT 2: A NEWEST-ONLY DEFAULT FUNCTION OF AN OLD STRUCTURE
  Cause: Mathlib v4.34.1 added `preTransparency := .instances` to `structure
  Convert.CheapConfig extends Congr!.Config` (Mathlib/Tactic/Convert.lean); v4.32.2 and v4.33.1
  do not have it (fetched at the three tags). The newest Mathlib therefore has the constant
  Convert.CheapConfig.preTransparency._default (.instances), the old ones only
  ..._inherited_default (.reducible) (Lean/Elab/Structure.lean:1390-1392). The merge kept every
  newest-only constant except realizations of old declarations, so the hybrid held both, and the
  delaborator (Lean/PrettyPrinter/Delaborator/Builtins.lean, collectStructFields) asks
  getEffectiveDefaultFnForField? (Lean/Structure.lean:316-318), which tries `_default` before
  `_inherited_default`: it found the newest `.instances`, isDefEq against the old value
  `.reducible` failed, and the field was printed. The newest Lean's printer behaves the same on the
  same data; the data was not the old version's. Not drift.
  Fix (Assemble.lean, rewriteMerge): a newest-only constant named <S>.<field>.<suffix>, where S is
  an old constant and the suffix is one Lean's own mkDefaultFnOfProjFn /
  mkInheritedDefaultFnOfProjFn / mkAutoParamFnOfProjFn appends, is dropped and counted
  ("newest-only default and autoParam functions of old structures' fields dropped").
  On M: 42 dropped (v4.32.2), 14 (v4.33.0), 14 (v4.33.1). On the sample: 10 on v4.31.0 and
  v4.32.2, 1 on v4.33.0 and v4.33.1 (1 is the gate's own probe; the other 9, elsewhere in the
  closure, were not listed by name).
