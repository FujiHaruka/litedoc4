# Every tools/*-gate.sh, and who runs it.
#
# A check nobody runs and a list naming a check nobody wrote are the same bug
# from two ends. There was no inventory for the gates themselves, and it cost —
# a gate over the measurement target had never once been run (measured
# 2026-08-28, fixed 2026-08-29), and another still carried the module count and
# the whole-package artefact names of a tree from before the UI was rewritten.
#
# COLUMN 2 — `ci` means a workflow invokes it, and `tools/workflow-gate.sh`
# checks that it really does. `manual` means it needs the measurement target, a
# clone of it, or a second package, so a free runner cannot have it; the gate
# checks those are *not* wired into CI, because a label that lies is worse than
# no label.
#
# COLUMN 3 — what it needs, in enough words that a reader knows why it is where
# it is. Nothing parses it.
#
# script                     who     needs
assets-embed-gate.sh         ci      nothing; reads the tree
assets-gate.sh               ci      node, via mise; the site's TypeScript
base-ir-gate.sh              manual  the target's IR at $PURELEAN_WORK; elan for the Lean litedoc4
benchmarks-ts-gate.sh        ci      deno; type-checks benchmarks/tools
docs-gate.sh                 ci      nothing; reads the tracked files
flag-tie-gate.sh             ci      elan, which builds the litedoc4 every documented flag is handed to
gc-table-gate.sh             manual  deno for the emitter arm; UnicodeBasic in the target for the arm that re-asks the ranges, and it arrives only with doc-gen4
lake-package-gate.sh         ci      elan and e2e/consumer
lean-test-gate.sh            ci      elan and a Lean package to borrow a toolchain from
lean-versions-gate.sh        ci      one IR tree per toolchain in lean-toolchains.txt

md-memory-gate.sh            ci      the system compiler with AddressSanitizer over the C Lake links in; the leak half needs a platform LeakSanitizer runs on
md-oracle-gate.sh            ci      nothing; reads fixtures/md/ and test/
