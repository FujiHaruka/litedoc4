M, one version natively: the extractor writes each module's IR as soon as the module is analyzed
================================================================================================

Before: every declaration's analysis result was held until the end and the IR tree written by one
thread. After: workers take whole modules; each module is analyzed, sorry-tagged, written to
modules/<M>.json and dropped; index.json and the dependency maps are written last. Kept per module:
counters, the index entry, its dependency pairs, one kind string per declaration (plus the
--dump / --dump-refs / --decl-profile payloads, only when those flags are given).

Conditions: Apple M1, 16 GB, macOS 26.6.2; Lean v4.33.1, Mathlib v4.33.1 (0df444a360); the M slice
(438 modules, 21,928 declarations), the checkout of benchmarks/results/mv-m-parallel-hash-2026-10-11.txt.
litedoc4 at 96f0f6a (base) and 96f0f6a + this change (new). Warm, same session, one run per arm
(the user's rule for levers: one run, +-10% accepted).

direct = the extractor alone under `lake env`, /usr/bin/time -l:
  extract <modules.txt> <events> --equations --refs --write-ir --tagged-code
          --no-equations-under Mathlib.Meta,Mathlib.Tactic --jobs N --ir-dir <ir> --link-index <lidx>
          --link-index-omit <modules.txt>
build  = litedoc4 build --root <checkout> --lib Mathlib --out <empty> --extractor-bin <x> --jobs N

store entries differ only through the identity string.
