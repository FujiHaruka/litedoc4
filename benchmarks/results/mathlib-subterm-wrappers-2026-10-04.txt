What the subterm wrappers in a signature are for, and how many wrap one token
=============================================================================
2026-10-04

What they are for: layout only. `<span class="fn">` gets one CSS rule (assets/style.css, §9,
taken from doc-gen4): `display: inline-block`, a hanging indent (`text-indent: -1ex;
padding-left: 1ex`), `white-space: pre-wrap`, `vertical-align: top` — so a long signature wraps
whole subterms and a wrapped subterm sits under its opener. No `:hover` rule and no script in
web/src reads the class (checked by grep at 1a5159c). There is no hover effect.

How many wrap a single token (no tag inside, no whitespace except one trailing space), over every
module page of the site of mathlib-signature-shape-2026-10-04.txt (measured):

  sample, first 20 pages in path order     43,808 wrappers, 24,093 single-token (55%)
  all 8,170 pages                      10,285,239 wrappers, 5,461,099 single-token (53.1%)

A single-token inline-block cannot be broken inside anyway, and its indent and padding cancel on
its one line, so these are expected to change nothing on screen (assumed — not rendered and
compared).

Script (run as: python3 fnatoms.py <site> <limit; 0 = all>):
import os, re, sys
SITE, LIMIT = sys.argv[1], int(sys.argv[2])
FN = re.compile(rb'<span class="fn">')
ATOM = re.compile(rb'<span class="fn">[^<\s]*\s?</span>')
files = [os.path.join(d, f) for d, _, fs in os.walk(SITE) for f in fs
         if f.endswith('.html') and (d.startswith(SITE + '/Mathlib') or f == 'Mathlib.html')]
files.sort()
if LIMIT: files = files[:LIMIT]
fn = atom = 0
for p in files:
    b = open(p, 'rb').read()
    fn += len(FN.findall(b)); atom += len(ATOM.findall(b))
print('pages', len(files), 'fn', fn, 'atom', atom, 'share', round(atom / max(fn, 1), 4))
