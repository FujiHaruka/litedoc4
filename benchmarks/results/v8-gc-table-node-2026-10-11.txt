The scan was made to fail once first: U+088F appended to one module
docstring of a copy of that IR gave 1 hit in both rows. The work directory was
deleted afterwards.

Even a hit would move no byte of a page: by the rule written at
`Litedoc4.Global.V8Gc`, nothing that produces bytes uses this table. It only
decides which tokens a code span offers to the map delta, i.e. which modules
are re-rendered when a name moves.

6. What this changes elsewhere (theoretical, not run)
-----------------------------------------------------

tools/make-target2.sh writes Beta/TokenSep.lean around U+088F as "the first of
the 4,803 code points V8 splits tokens on and UnicodeBasic does not". Under
node, U+088F is a separator for neither table, so that fixture no longer
exercises the direction it names. It is read only by the manual target2 gate,
which needs the measurement target and was not run here.
