How often the .olean data layouts changed across the Lean versions of Mathlib's releases
========================================================================================
2026-10-04

What this answers
-----------------
docs/multiversion/plan.md D10 chose an own `.olean` reader running in one Lean. The reader walks
the compacted object graph generically (every object carries its tag, object-field count and
scalar size); what it must know per Lean version is how to *interpret* the objects. Question:
between consecutive Lean versions used by Mathlib v4.29.0 .. v4.34.1, how many times did anything
the reader interprets change, and of what kind?

Answer (10 adjacent pairs, v4.29.0 -> v4.34.1)  (measured: source diffs on all 10 pairs,
reflection on the 5 installed toolchains; see "Which pairs are validated how")
  pairs with >= 1 layout change                      3 of 10   (v4.29.1->v4.30.0, v4.30.0->v4.31.0,
                                                                v4.32.2->v4.33.0)
    of them, changing the representation of an
    object the reader decodes (not just which
    extensions exist or which file holds them)       2 of 10   (v4.30.0->v4.31.0, v4.32.2->v4.33.0)
  pairs with >= 1 meaning change                     1 of 10   (v4.32.2->v4.33.0: ReducibilityStatus)
  pairs with no change at all                        7 of 10   (all 5 patch pairs, v4.31.0->v4.32.0,
                                                                v4.33.1->v4.34.0)
  .olean header / compactor object encoding          0 changes in 10 pairs
  ModuleData and the .olean/.olean.server/
  .olean.private split                               0 changes in 10 pairs
  Name / Level / Expr / Literal / BinderInfo /
  ConstantInfo and every *Val, incl. computed
  fields, Expr.Data / Level.Data and hashes          0 changes in 10 pairs
  commits touching the component files judged
  cosmetic                                           178 (per-range count; release-branch
                                                         backports appear in two ranges)

The positive control (implicit_reducible -> instance_reducible, tools/lean-toolchains.txt column 2)
is found by all three methods, in v4.32.2 -> v4.33.0 — see "Positive control".

Changes, one row per pair x component (layout and meaning only)
---------------------------------------------------------------
Kinds: layout = representation or presence changed; meaning = same layout, different
interpretation or different value written. "placement" is a layout change in which of the three
files holds an entry; `.olean.private` holds every entry — measured on the 5 installed toolchains
(core library), and read from the wrappers' export functions for the other tags — so a reader that
loads all three parts in order is unaffected by placement changes.

For the reader: one version-specific decoding branch per changed type, keyed by the header's Lean
version — 3 types (ReducibilityStatus, SimpTheorem, ElabBlock/ElabInline as one) across the window —
plus one meaning table (what ReducibilityStatus cidx 3 means before / from v4.33.0).

Facts that hold in every version of the window (measured on 5 toolchains, source on all 12 tags):
  - the 3-file split dates from v4.20.0 (`OLeanLevel.adjustFileName` absent in v4.19.0 source,
    present in v4.20.0); `.olean.server` and `.olean.private` reference objects in the earlier
    parts (one compactor across the parts), so they are loaded together with readModuleDataParts.
    A file without the `module` header writes a single `.olean` (2 of 2,520 core modules in
    v4.34.1: Leanc, LeanChecker); Mathlib's oleans at the target's v4.31.0 pin are 3-part.
  - `.olean.private` is a superset: of the tier-1/2 extension names that have entries anywhere in
    the core library (41 on v4.34.1), all have entries in `.olean.private`; docStringExt,
    declRangeExt, moduleDocExt, inheritDocStringExt, versoDocStringExt, versoModuleDocExt have none
    in `.olean` (except in the 2 single-file modules). The pattern is identical on all 5
    toolchains. 7 tier-1/2 extensions have no entries in the core library at all (tacticTagExt,
    tacticDocExtExt, docInlineMdExt, docBlockMdExt, DeferredCheck.handlerExt, eqnOptionsExt,
    reducibilityExtra), so their placement is known from source only.
  - header flags bit 0 (GMP bignum encoding) = 1 on all 5 toolchains.

Positive control
----------------
tools/lean-toolchains.txt column 2: v4.31.0 / v4.32.2 write `implicit_reducible` for a reducible
instance, v4.33.0 / v4.33.1 write `instance_reducible`. The method finds it three ways, all in
v4.32.2 -> v4.33.0 and nowhere else in the window:
  1. source: the block diff of `inductive ReducibilityStatus` (constructor appended) and the
     docstring rewrite of the same commit (the meaning of cidx 3) — rows above;
  2. reflection: `Lean.ReducibilityStatus ctors=4 -> ctors=5`, new `instanceReducible cidx=4`;
  3. written values: the distribution in the facts table below — 8,162 -> 4 instance definitions
     at [implicit_reducible], 0 -> 8,250 at [instance_reducible].
The optional pair v4.28.0 -> v4.29.0 shows the earlier step (cidx 3 appended) by source.

Method
------
1. Source (all 12 tags). blocks.py extracts, for each of 200 targets (the 112 closure types and 46
   extension constants from the reflection run, plus the Expr/Level data constructors, hash and
   quickCmp functions, the wrapper export functions, mkModuleData / writeModule / computeExtEntries /
   save/readModuleDataParts and the extractor's lookup functions), the definition block from its
   v4.34.1 module file at every tag, strips comments and docstrings, and diffs adjacent tags. Every
   target was found at every tag except those that did not exist yet (exportedAxiomsExt,
   OLeanEntries, computeExtEntries: from v4.30.0; Name.quickCmpImpl: from v4.29.0;
   findSimpleDocString?, which moved file in v4.33.0 and is tracked in both files). C/C++ files
   (header, compactor, object layouts, hashes) were diffed whole per pair; lean.h's object
   structs and kind constants were extracted and diffed per pair (only lean_task_imp /
   lean_task_object changed, in v4.33.0 — tasks are never in an .olean); lean_string_hash,
   hash_str and lean_expr_mk_data / mk_app_data have the same digest at all 12 tags. Each change
   was attributed with `git log vA..vB -- <files>` and read in the commit; everything else touching
   the 74 component files + 5 Std container directories + 6 kernel/util C++ files is counted
   cosmetic.
2. Reflection (5 toolchains). layout.lean, run with `lean layout.lean` per toolchain: the closure
   of the root types (constructors, field names and types as de Bruijn terms, `_impl` constructors
   for computed fields, `getCtorLayout` of each — 227/230 layouts, 0 errors on every toolchain), the
   types of the 46 extension constants, every registered persistent extension name, Name.hash of 6
   names, Level.data of 5 levels, Expr.data of 11 expressions, and a quickLt sort. parts.lean reads
   every .olean of the toolchain's own library with all its parts via readModuleDataParts and counts
   entries per extension per part. facts.lean tabulates the persisted per-declaration facts over
   the whole `import Lean` environment (~204–208 k constants).
3. The script runs were sampled first (LAYOUT_LIMIT=4, PARTS_LIMIT=20, FACTS_LIMIT=20) and then run
   in full.

What could not be checked, and why
----------------------------------
- Reflection on v4.28.0, v4.29.0, v4.29.1, v4.30.0, v4.32.0, v4.32.1, v4.34.0: those toolchains are
  not installed, and installing them was out of bounds (disk). Their pairs rest on source reading;
  31.0->32.2 and 33.1->34.1 are validated only as aggregates.
- Writer-side meaning changes before v4.31.0: the facts table needs a toolchain, so the
  v4.28.0->v4.29.0 reducibility shift (instances moving off `semireducible`) is source-only and not
  counted; within 29.0->31.0 no meaning change was found by source, but none could be measured.
- The facts table covers only the dimensions it tabulates (reducibility x kind x instance, hints,
  safety, instance priority/kind, simp membership, declaration-range shape, docstring presence and
  ends, private names, structure/class/noncomputable/auxRecursor/noConfusion/csimp/deprecated). A
  meaning change elsewhere — e.g. in what a declaration range spans, or in docstring text
  normalisation — would not show; source diffs of those functions showed none.
- No independent decoder was written: the object encoding is judged unchanged from the source
  (lean.h structs, compact.cpp, module.cpp) and from the header bytes of each toolchain's oleans,
  not by decoding an .olean of one version with code written for another.
- Only the toolchains' own core libraries were read (2,421–2,520 modules); no Mathlib .olean was
  read. Extensions with no entries in core (7 listed above) have source-only placement.
- Tier 2 stops at per-constant facts; delaborator / parser-table / formatter extensions were not
  examined (by design, see component D). Equations, first-token tactic names and Verso -> Markdown
  rendering are computations, not data a reader can decode, whatever the layout.
- Extension-constant types and registered names before v4.31.0 come from source only; the
  `private` keyword (which renames a registered extension) was checked in each block diff.

    `quickLt` order. A writer-side meaning change (same layout, different value written for the same

      m.insert k (m.getD k 0 + 1)
    
    #eval show CoreM Unit from do
      let lim := ((← IO.getEnv "FACTS_LIMIT").bind String.toNat?).getD 10000000
      let env ← getEnv
      let names := (env.constants.map₁.toList.map (·.1)).toArray.qsort Name.quickLt |>.extract 0 lim
      let insts := (Meta.instanceExtension.getState env).instanceNames
      let thms ← simpExtension.getTheorems
      let mut m : Std.HashMap String Nat := {}
      for n in names do
        let some ci := env.find? n | continue
        let kind := match ci with
          | .axiomInfo _ => "axiom" | .defnInfo _ => "def" | .thmInfo _ => "thm"
          | .opaqueInfo _ => "opaque" | .quotInfo _ => "quot" | .inductInfo _ => "induct"
          | .ctorInfo _ => "ctor" | .recInfo _ => "rec"
        let inst := if insts.contains n then "inst" else "noinst"
        m := bump m s!"kind {kind}"
        let st := getReducibilityStatusCore env n
        m := bump m s!"reducibility {kind} {inst} {st.toAttrString}"
        if let .defnInfo d := ci then
          let h := match d.hints with
            | .opaque => "opaque" | .abbrev => "abbrev" | .regular _ => "regular"
          m := bump m s!"hints {inst} {h}"
          m := bump m s!"safety {repr d.safety}"
        if let some e := insts.find? n then
          m := bump m s!"instance priority {if e.priority == 1000 then "default" else "other"} attrKind {toString e.attrKind}"
        if thms.isLemma (.decl n) then m := bump m "simp lemma"
        match ← findDeclarationRanges? n with
        | none => m := bump m "ranges none"
        | some r =>
          m := bump m (if r.range == r.selectionRange then "ranges sel==range" else "ranges sel!=range")
          if r.range.pos.column == 0 then m := bump m "ranges col0"
        match ← findDocString? env n with
        | none => m := bump m "doc none"
        | some d =>
          m := bump m "doc some"

          if d.endsWith "\n" then m := bump m "doc trailing-newline"

        if isStructure env n then m := bump m "structure"

        if (Linter.deprecatedAttr.getParam? env n).isSome then m := bump m "deprecated"

blocks.py (`python3 blocks.py <targets.tsv> <limit>`; targets.tsv rows are `name<TAB>path under src/`)
    """Extract the definition block of each named type / extension / function from the Lean sources of
    every tag, normalise away comments and whitespace, and print the blocks that differ between
    adjacent tags. Usage: blocks.py <targets.tsv> <limit> ; targets.tsv rows are `name<TAB>module`."""
    import difflib
    import re
    import sys
    from pathlib import Path
    
    ROOT = Path("<scratch>/lean4-src-tags")
    TAGS = ["v4.28.0", "v4.29.0", "v4.29.1", "v4.30.0", "v4.31.0", "v4.32.0", "v4.32.1",
            "v4.32.2", "v4.33.0", "v4.33.1", "v4.34.0", "v4.34.1"]
    KW = r"(?:structure|inductive|class inductive|class|abbrev|def|opaque|builtin_initialize|initialize)"
    MODS = r"(?:(?:private|protected|public|unsafe|partial|noncomputable|meta)\s+)*"
    
    
    def strip_comments(text):
        out, i, depth = [], 0, 0
        while i < len(text):
            if text.startswith("/-", i):
                depth += 1
                i += 2
                continue
            if depth and text.startswith("-/", i):
                depth -= 1
                i += 2
                continue
            if depth:
                i += 1
                continue
            if text.startswith("--", i):
                j = text.find("\n", i)
                i = len(text) if j < 0 else j
                continue
            out.append(text[i])
            i += 1
        return "".join(out)
    
    
    def block(path, short):
        if not path.exists():
            return None
        lines = path.read_text().split("\n")
        pat = re.compile(r"^\s*(?:@\[[^\]]*\]\s*)*" + MODS + KW + r"\s+(?:\w+\s+)?(?:[\w.]+\.)?«?" + re.escape(short) + r"»?(?![\w.'!?])")
        found = []
        for i, l in enumerate(lines):
            if pat.match(l):
                j = i + 1
                while j < len(lines):
                    nl = lines[j]
                    if nl.strip() == "":
                        j += 1
                        continue
                    if nl[0] in " \t|" or nl.startswith("deriving") or nl.startswith("with") \
                            or nl.startswith("@[computed_field]"):
                        j += 1
                        continue
                    break
                found.append("\n".join(lines[i:j]))
        if not found:
            return None
        txt = strip_comments("\n\n".join(found))
        return [l.rstrip() for l in txt.split("\n") if l.strip()]
    
    
    def main():
        rows = [l.split("\t") for l in Path(sys.argv[1]).read_text().split("\n") if l.strip()]
        limit = int(sys.argv[2])
        rows = rows[:limit]
        for name, path in rows:
            short = name.split(".")[-1]
            prev = None
            for k, tag in enumerate(TAGS):
                cur = block(ROOT / tag / "src" / path, short)
                if k > 0 and cur != prev:
                    print(f"=== {name} [{path}] {TAGS[k-1]} -> {tag}")
                    if prev is None or cur is None:
                        print(f"    {'absent' if prev is None else 'present'} -> {'absent' if cur is None else 'present'}")
                    else:
                        for d in difflib.unified_diff(prev, cur, lineterm="", n=1):
                            if d.startswith(("---", "+++")):
                                continue
                            print("    " + d)
                prev = cur
            print(f"--- checked {name}")
    
    
    if __name__ == "__main__":
        main()
