# What 1.x keeps. One line per name a consumer's own files can contain.
#
# The rule that decides what belongs here: **can it appear in a file someone else
# maintains?** A GitHub workflow names the action's inputs and reads its outputs;
# a `litedoc4.toml` names its keys; a script names `build`'s and `watch`'s flags;
# a link into the site names a page path and an anchor. Those break other people's
# files when they move. The IR schema, the ledger and `.lidx` do not: a consumer
# pins one ref, and the action and the Lake script resolve the binary by the
# version in *that* ref, so the two halves always come from the same tree.
#
# ONE DIRECTION, ON PURPOSE
#   Adding an input, a flag or a key does not break anyone. Removing or renaming
#   one does. So the checks ask "is every promised name still there", and only
#   action.yml is asked the other way too — it is plain data, so it costs nothing,
#   and it makes a rename read as one added plus one removed rather than as two
#   unrelated lines.
#
# The reader is tools/public-surface-gate.sh; README's "Status" quotes it.

# Page paths and declaration anchors keep doc-gen4's shape — `Foo/Bar.html` and
# `#Foo.bar` — so links into an existing site survive. That one is not a list of
# names, so nothing above can carry it: it is held by the 49 frozen files of
# `e2e/micro-expected`, which `tools/purelean-micro-gate.sh` compares byte for
# byte. The shape is in the tree layout (`build/Example/Basic.html`) and in the
# `id=` attributes of the pages (`id="Example.double"`), so a renamed page path or
# a re-spelled anchor is a diff there rather than a silent break in somebody's
# link. `tools/site-gate.sh` then asks that the index and the pages agree about
# those anchors in both directions.
