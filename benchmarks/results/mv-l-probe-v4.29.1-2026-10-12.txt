THE CAUSE (read in Lean's sources)
---------
Lean v4.30.0 added `exportedAxiomsExt` to Lean/Util/CollectAxioms.lean: each module's olean stores
the axiom list of each of its declarations, and `collectAxioms` on an imported constant is a lookup.
v4.29.1's CollectAxioms.lean has no such extension (fetched from leanprover/lean4 at both tags,
2026-10-12): oleans built by v4.29.x carry no axiom lists. Extract.lean's sorry tag calls
`collectAxioms` once per declaration, and with no stored list the 4.34.1 implementation walks the
declaration's whole dependency closure, proofs included, with a visited set that lives for that one
call. Every Mathlib declaration's closure reaches the foundations, so the same closure is walked
again for each of ~300,000 declarations.

At the sampled rate (85 IR files in 6 min) the remaining ~6,800 files would take ~8 h (extrapolated
from 6 min of one run; the rate is not constant across modules). The four-hour run of
mv-l-full-2026-10-12.txt is consistent with this. v4.29.0's CollectAxioms.lean has no such extension
either (fetched the same way), so v4.29.0 is in the same case.
