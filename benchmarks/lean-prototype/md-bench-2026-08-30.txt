WHAT MARKDOWN ITSELF COSTS — `page.render`, sequential, medians of 5
  --ablate doc  (docstrings escaped, nothing else)     0.506
  no --md       (backtick scan + autoLinkInline)       0.625   -> 0.119
  --md          (md4c + the html.rs transcription)     0.661   -> 0.155
  So the docstring path costs 0.155 s of a 1.07 s command, and 0.119 s of that
  was already being paid by the scan it replaces. **Marginal cost of real
  Markdown: +0.036 s, 3.4% of the command.**

FRICTION
  - no usable tag (only `v4.19.0-rc1`); pinned main's SHA
  - MD4Lean's `lean-toolchain` is v4.29.0-rc1, **lower** than the prototype's
    v4.31.0, so `lake update` left ours alone. A higher one would have rewritten
    it
  - MD4Lean uses the experimental module system (`module` / `public section`);
    importing it from a plain non-module file needed no configuration
  - built and ran on v4.31.0 first try, no patch, no API mismatch
  - it does **not** answer the Unicode general category `P | Z | C` that
    `mdGetHeadingId` needs. The 839 ranges from `crates/litedoc4-md/src/gc.rs`
    are embedded here as a string literal; a real implementation takes the
    `UnicodeBasic` package doc-gen4 already requires — **a second git dependency
    that is not in these build numbers**
  - it does not do LaTeX -> MathML either (`math.rs`, 179 lines)
